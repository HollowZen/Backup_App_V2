## 1. ВВЕДЕНИЕ

### 1.1. Общая характеристика

Система управления резервным копированием данных представляет собой полнофункциональное настольное приложение для Windows, предназначенное для автоматизированного создания, управления и хранения резервных копий файлов и папок. Приложение обеспечивает высокий уровень защиты данных за счет использования современных алгоритмов шифрования и предоставляет гибкие возможности настройки процессов резервного копирования.

### 1.2. Актуальность разработки

В современном мире информационных технологий проблема сохранности данных является критически важной. Потеря важной информации может привести к серьезным последствиям для пользователей и организаций. Разработанная система решает следующие задачи:

- Автоматизация процесса создания резервных копий
- Обеспечение безопасности данных через шифрование
- Оптимизация использования дискового пространства
- Упрощение управления процессами резервного копирования
- Предоставление гибких настроек расписания выполнения задач

## 2. НАЗНАЧЕНИЕ И ОБЛАСТЬ ПРИМЕНЕНИЯ

### 2.1. Назначение системы

Система предназначена для:

1. **Автоматического резервного копирования** файлов и папок по заданному расписанию
2. **Защиты данных** посредством шифрования AES-256
3. **Оптимизации хранения** через применение политик управления версиями
4. **Мониторинга выполнения** задач резервного копирования
5. **Управления задачами** через удобный графический интерфейс

### 2.2. Область применения

Система может использоваться:

- В домашних условиях для резервного копирования личных данных
- В малом и среднем бизнесе для защиты корпоративной информации
- В образовательных учреждениях для сохранения учебных материалов
- В организациях, требующих соблюдения политик информационной безопасности

### 2.3. Основные функции

#### 2.3.1. Типы резервного копирования

1. **Полное копирование (Full Backup)**
   - Копирование всех файлов из указанной директории
   - Используется для создания базовой точки восстановления
   - Требует наибольшего объема хранилища

2. **Инкрементальное копирование (Incremental Backup)**
   - Копирование только файлов, измененных с момента последнего бэкапа
   - Экономит дисковое пространство
   - Требует наличия предыдущих версий для восстановления

3. **Дифференциальное копирование (Differential Backup)**
   - Копирование файлов, измененных с момента последнего полного бэкапа
   - Компромисс между полным и инкрементальным копированием
   - Упрощает процесс восстановления

#### 2.3.2. Планирование задач

- **Ручной запуск**: Выполнение по требованию пользователя
- **Ежедневное выполнение**: Запуск в указанное время каждый день
- **Еженедельное выполнение**: Запуск в указанные дни недели
- **Ежемесячное выполнение**: Запуск в указанный день месяца

#### 2.3.3. Сжатие данных

- Поддержка ZIP-архивации с настраиваемым уровнем сжатия (0-9)
- Оптимизация использования дискового пространства
- Баланс между размером архива и скоростью создания

#### 2.3.4. Шифрование данных

- Шифрование AES-256-CBC
- Генерация ключей через PBKDF2
- Безопасное хранение паролей через Windows DPAPI

#### 2.3.5. Управление версиями

- Политика "Хранить все": Сохранение всех версий бэкапов
- Политика "Максимум версий": Ограничение количества хранимых версий
- Политика "Максимальный возраст": Автоматическое удаление старых версий

### 4.3. Паттерны проектирования

#### 4.3.1. Model-View-ViewModel (MVVM)

**Применение**: Разделение логики представления и бизнес-логики.

**Преимущества**:
- Тестируемость: ViewModels могут тестироваться независимо от UI
- Переиспользование: Логика может использоваться в разных представлениях
- Поддержка: Изменения в UI не требуют изменений в бизнес-логике

**Реализация**:
- `View`: XAML файлы с минимальным code-behind (только `InitializeComponent()`)
- `ViewModel`: Классы, наследующие `ObservableObject`, содержат всю бизнес-логику
- `Model`: Классы из `BackupApp.Core.Models`
- **Привязка данных**: Использование `PasswordBoxBindingBehavior` для двухсторонней привязки паролей
- **Команды**: Все действия пользователя реализованы через `RelayCommand` (реализация `ICommand`)
- **Code-behind**: Содержит только вызов `InitializeComponent()`, вся логика в ViewModels

#### 4.3.2. Repository Pattern

**Применение**: Абстракция доступа к данным.

**Реализация**:

## 5. ОПИСАНИЕ КОМПОНЕНТОВ

### 5.1. Сервис резервного копирования (BackupService)

#### 5.1.1. Назначение

Основной сервис, отвечающий за выполнение операций резервного копирования. Обеспечивает:
- Выбор файлов для копирования в зависимости от типа бэкапа
- Создание ZIP-архивов с настраиваемым уровнем сжатия
- Копирование файлов в целевую директорию
- Интеграцию с сервисом шифрования

#### 5.1.2. Основные методы

**ExecuteBackupAsync**
```csharp
Task<BackupExecutionResult> ExecuteBackupAsync(
    BackupTask task, 
    IProgress<BackupProgressReport>? progress = null, 
    CancellationToken cancellationToken = default)
```

**Алгоритм работы**:
1. Проверка существования исходной директории
2. Создание целевой директории при необходимости
3. Выбор файлов для копирования (в зависимости от типа бэкапа)
4. Создание архива или прямое копирование
5. Шифрование архива (если включено)
6. Формирование результата выполнения

**DecryptBackupAsync**
```csharp
Task<BackupExecutionResult> DecryptBackupAsync(
    string encryptedFilePath, 
    string outputDirectory, 
    string password, 
    CancellationToken cancellationToken = default)
```

**Алгоритм работы**:
1. Проверка существования зашифрованного файла
2. Расшифровка файла
3. Распаковка архива (если применимо)
4. Сохранение файлов в целевую директорию

#### 5.1.3. Выбор файлов для копирования

**Полное копирование (Full)**:
- Копируются все файлы из исходной директории

**Инкрементальное копирование (Incremental)**:
- Копируются файлы, измененные после `LastBackupTime`
- Используется сравнение времени модификации файлов

**Дифференциальное копирование (Differential)**:
- Копируются файлы, измененные после `LastFullBackupTime`
- Требует наличия полного бэкапа

### 5.2. Сервис шифрования (EncryptionService)

#### 5.2.1. Назначение

Обеспечивает криптографическую защиту данных с использованием алгоритма AES-256.

#### 5.2.2. Технические характеристики

- **Алгоритм**: AES (Advanced Encryption Standard)
- **Размер ключа**: 256 бит
- **Режим работы**: CBC (Cipher Block Chaining)
- **Дополнение**: PKCS7
- **Размер блока**: 128 бит
- **Генерация ключа**: PBKDF2 (Password-Based Key Derivation Function 2)
- **Количество итераций PBKDF2**: 10,000
- **Размер соли**: 32 байта (256 бит)

#### 5.2.3. Алгоритм шифрования

```
1. Генерация случайной соли (32 байта)
2. Генерация случайного вектора инициализации IV (16 байт)
3. Вывод ключа из пароля через PBKDF2:
   Key = PBKDF2(Password, Salt, 10000 iterations, 32 bytes)
4. Запись IV и соли в начало файла
5. Шифрование данных через AES-256-CBC
6. Сохранение зашифрованных данных
```

#### 5.2.4. Алгоритм расшифровки

```
1. Чтение IV и соли из начала файла
2. Вывод ключа из пароля через PBKDF2
3. Расшифровка данных через AES-256-CBC
4. Сохранение расшифрованных данных
```

#### 5.2.4. Безопасность паролей

Пароли шифрования хранятся в зашифрованном виде с использованием Windows DPAPI (Data Protection API):

```csharp
// Шифрование пароля
byte[] encrypted = ProtectedData.Protect(
    Encoding.UTF8.GetBytes(password),
    entropy,
    DataProtectionScope.CurrentUser
);

// Расшифровка пароля
byte[] decrypted = ProtectedData.Unprotect(
    encrypted,
    entropy,
    DataProtectionScope.CurrentUser
);
```

**Преимущества DPAPI**:
- Интеграция с системой безопасности Windows
- Пароли доступны только текущему пользователю
- Автоматическое управление ключами

### 5.3. Планировщик задач (SchedulerService)

#### 5.3.1. Назначение

Обеспечивает автоматическое выполнение задач резервного копирования по расписанию.

#### 5.3.2. Архитектура планировщика

Планировщик использует двухуровневую систему таймеров для обеспечения точности выполнения:

**Основной таймер (Main Timer)**:
- Интервал: 30 секунд
- Назначение: Обнаружение задач, требующих выполнения
- Эффективность: Минимальная нагрузка на систему

**Точный таймер (Precision Timer)**:
- Интервал: 5 секунд
- Назначение: Точное выполнение задач в указанное время
- Активация: Включается за 45 секунд до ближайшего запуска
- Деактивация: Отключается после выполнения или если ближайший запуск более чем через 45 секунд

#### 5.3.3. Алгоритм работы

```
1. Запуск основного таймера (каждые 30 секунд)
2. Получение списка активных задач из базы данных
3. Для каждой задачи:
   a. Вычисление времени следующего запуска
   b. Проверка необходимости выполнения
   c. Запуск задачи в фоновом потоке
4. Определение ближайшего времени запуска
5. Если ближайший запуск < 45 секунд:
   a. Включение точного таймера (каждые 5 секунд)
6. Повторение процесса
```

#### 5.3.4. Вычисление времени следующего запуска

**Ежедневное расписание**:
```
NextRun = Сегодня в указанное время
Если NextRun < Текущее время:
    NextRun = Завтра в указанное время
```

**Еженедельное расписание**:
```
1. Определение указанных дней недели
2. Поиск ближайшего дня из списка
3. NextRun = Ближайший день в указанное время
```

**Ежемесячное расписание**:
```
1. Определение указанного числа месяца
2. NextRun = Текущий месяц, указанное число, указанное время
Если NextRun < Текущее время:
    NextRun = Следующий месяц, указанное число, указанное время
```

#### 5.3.5. Защита от повторного запуска

- Использование `ConcurrentDictionary` для отслеживания выполняющихся задач
- Проверка времени последнего запуска
- Предотвращение одновременного выполнения одной задачи

### 5.4. Сервис управления версиями (RetentionService)

#### 5.4.1. Назначение

Управление хранением старых версий резервных копий в соответствии с заданными политиками.

#### 5.4.2. Типы политик

**KeepAll (Хранить все)**:
- Сохраняются все версии бэкапов
- Не выполняется автоматическая очистка

**MaxVersions (Максимум версий)**:
- Сохраняется только указанное количество последних версий
- Старые версии удаляются автоматически

**MaxAge (Максимальный возраст)**:
- Удаляются версии старше указанного количества дней
- Вычисляется на основе даты создания бэкапа

#### 5.4.3. Алгоритм применения политики

```
1. Получение списка всех версий для задачи
2. Сортировка по дате создания (от новых к старым)
3. В зависимости от типа политики:
   a. MaxVersions: Удаление версий после N-й
   b. MaxAge: Удаление версий старше N дней
4. Удаление файлов и записей из базы данных
```

### 5.5. Репозиторий задач (BackupTaskRepository)

#### 5.5.1. Назначение

Абстракция доступа к данным о задачах резервного копирования.

#### 5.5.2. Основные операции

- **GetAllAsync**: Получение всех задач
- **GetByIdAsync**: Получение задачи по идентификатору
- **AddAsync**: Добавление новой задачи
- **UpdateAsync**: Обновление существующей задачи
- **DeleteAsync**: Удаление задачи
- **UpdateLastRunAsync**: Обновление времени последнего выполнения

## 8. БЕЗОПАСНОСТЬ ДАННЫХ

### 8.1. Криптографическая защита

#### 8.1.1. Алгоритм шифрования AES-256

**Характеристики**:
- **Размер ключа**: 256 бит (32 байта)
- **Размер блока**: 128 бит (16 байт)
- **Режим работы**: CBC (Cipher Block Chaining)
- **Дополнение**: PKCS7

**Преимущества AES-256**:
- Признан стандартом шифрования правительством США
- Устойчив к известным атакам
- Эффективная реализация на современных процессорах

#### 8.1.2. Генерация ключей (PBKDF2)

**Параметры**:
- **Алгоритм хеширования**: SHA-256
- **Количество итераций**: 10,000
- **Размер соли**: 32 байта (256 бит)
- **Размер ключа**: 32 байта (256 бит)

**Функция вывода ключа**:
```
Key = PBKDF2(
    Password: Пароль пользователя,
    Salt: Случайная соль (32 байта),
    Iterations: 10000,
    HashAlgorithm: SHA-256,
    OutputLength: 32 байта
)
```

**Преимущества PBKDF2**:
- Защита от атак перебора (brute-force)
- Уникальная соль для каждого файла
- Настраиваемое количество итераций

#### 8.1.3. Вектор инициализации (IV)

- **Размер**: 16 байт (128 бит)
- **Генерация**: Криптографически стойкий генератор случайных чисел
- **Хранение**: В начале зашифрованного файла
- **Назначение**: Обеспечение уникальности шифрования для каждого файла

### 8.2. Хранение паролей

#### 8.2.1. Windows DPAPI

**Применение**: Шифрование паролей перед сохранением в базе данных.

**Преимущества**:
- Интеграция с системой безопасности Windows
- Пароли доступны только текущему пользователю Windows
- Автоматическое управление ключами шифрования
- Не требует дополнительных библиотек

**Реализация**:
```csharp
// Шифрование
byte[] entropy = Encoding.UTF8.GetBytes("BackupApp_Entropy");
byte[] encrypted = ProtectedData.Protect(
    Encoding.UTF8.GetBytes(password),
    entropy,
    DataProtectionScope.CurrentUser
);

// Расшифровка
byte[] decrypted = ProtectedData.Unprotect(
    encrypted,
    entropy,
    DataProtectionScope.CurrentUser
);
```

#### 8.2.2. Хранение в базе данных

Пароли хранятся в виде:
- Хеша пароля (PBKDF2 + соль)
- Зашифрованного через DPAPI значения
- В поле `EncryptionPasswordHash` таблицы `BackupTasks`

### 8.3. Защита от несанкционированного доступа

#### 8.3.1. Валидация паролей

- Минимальная длина: 8 символов
- Рекомендуется использование сложных паролей
- Проверка при создании задачи

#### 8.3.2. Обработка ошибок

- Безопасное сообщение об ошибках (без раскрытия деталей)
- Логирование ошибок без сохранения паролей
- Graceful degradation при ошибках шифрования

## 9. БАЗА ДАННЫХ

### 9.1. Технология

- **СУБД**: SQLite 3
- **ORM**: Entity Framework Core 8.0
- **Миграции**: Code First подход

### 9.2. Структура базы данных

#### 9.2.1. Таблица BackupTasks

**Назначение**: Хранение задач резервного копирования.

**Структура**:

| Поле | Тип | Описание |
|------|-----|----------|
| Id | INTEGER PRIMARY KEY | Уникальный идентификатор |
| Name | TEXT NOT NULL (200) | Название задачи |
| SourcePath | TEXT NOT NULL (1000) | Путь к исходной директории |
| TargetPath | TEXT NOT NULL (1000) | Путь к целевой директории |
| ScheduleType | INTEGER NOT NULL | Тип расписания (0-3) |
| ScheduleTime | TEXT (10) | Время выполнения (HH:mm) |
| ScheduleDays | TEXT (100) | Дни недели (для еженедельного) |
| ScheduleDayOfMonth | INTEGER | День месяца (для ежемесячного) |
| IsEnabled | INTEGER NOT NULL | Флаг активности (0/1) |
| CreatedDate | TEXT NOT NULL | Дата создания (UTC) |
| BackupType | INTEGER NOT NULL | Тип копирования (0-2) |
| UseCompression | INTEGER NOT NULL | Использование сжатия (0/1) |
| CompressionLevel | INTEGER NOT NULL | Уровень сжатия (0-9) |
| UseEncryption | INTEGER NOT NULL | Использование шифрования (0/1) |
| EncryptionPasswordHash | TEXT | Хеш пароля шифрования |
| RetentionPolicyType | INTEGER NOT NULL | Тип политики хранения (0-2) |
| MaxVersions | INTEGER | Максимальное количество версий |
| MaxAgeDays | INTEGER | Максимальный возраст в днях |
| LastBackupTime | TEXT | Время последнего выполнения |
| LastFullBackupTime | TEXT | Время последнего полного копирования |

**Индексы**:
- PRIMARY KEY на Id
- Индекс на IsEnabled (для быстрого поиска активных задач)

#### 9.2.2. Таблица BackupHistories

**Назначение**: История выполнения задач резервного копирования.

**Структура**:

| Поле | Тип | Описание |
|------|-----|----------|
| Id | INTEGER PRIMARY KEY | Уникальный идентификатор |
| BackupTaskId | INTEGER NOT NULL | Ссылка на задачу |
| ExecutionDate | TEXT NOT NULL | Дата выполнения (UTC) |
| Status | TEXT NOT NULL | Статус (Success/Failed) |
| FilesCopied | INTEGER | Количество скопированных файлов |
| BytesWritten | INTEGER | Записанных байт |
| Duration | TEXT | Длительность выполнения |
| ErrorMessage | TEXT | Сообщение об ошибке (если есть) |
| OutputPath | TEXT | Путь к созданному файлу |

**Связи**:
- FOREIGN KEY (BackupTaskId) REFERENCES BackupTasks(Id) ON DELETE CASCADE

**Индексы**:
- PRIMARY KEY на Id
- Индекс на BackupTaskId
- Индекс на ExecutionDate

#### 9.2.3. Таблица BackupSettings

**Назначение**: Глобальные настройки приложения.

**Структура**:

| Поле | Тип | Описание |
|------|-----|----------|
| Id | INTEGER PRIMARY KEY | Уникальный идентификатор |
| Key | TEXT NOT NULL UNIQUE | Ключ настройки |
| Value | TEXT | Значение настройки |
