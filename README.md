## 🚀 Основные возможности

### 📁 Типы резервного копирования

- **Полная копия (Full Backup)**: Копирование всех файлов из указанной директории. Используется для создания базовой точки восстановления.
- **Инкрементальная копия (Incremental Backup)**: Копирование только файлов, измененных с момента последнего бэкапа любого типа. Экономит дисковое пространство и время выполнения.
- **Дифференциальная копия (Differential Backup)**: Копирование файлов, измененных с момента последнего полного бэкапа. Баланс между экономией места и простотой восстановления.

### 🔒 Безопасность данных

- **Шифрование AES-256-CBC**: Промышленный стандарт шифрования с использованием алгоритма AES-256 в режиме CBC
- **PBKDF2 с SHA-256**: Генерация ключей из паролей с использованием PBKDF2 (10,000 итераций) и случайной соли
- **Windows DPAPI**: Безопасное хранение паролей шифрования в зашифрованном виде через Windows Data Protection API
- **Защита от несанкционированного доступа**: Пароли никогда не хранятся в открытом виде
- **Функция расшифровки**: Отдельное окно для расшифровки зашифрованных архивов с проверкой пароля

### 📅 Автоматическое планирование

- **Гибкое расписание**: 
  - Ручной запуск (Manual)
  - Ежедневное выполнение (Daily)
  - Еженедельное выполнение (Weekly) с выбором дней недели
  - Ежемесячное выполнение (Monthly) с выбором дня месяца
- **Двойная система таймеров**: 
  - Основной таймер (30 секунд) для проверки расписания
  - Точный таймер (5 секунд) для максимальной точности запуска в окне ±45 секунд
- **Фоновое выполнение**: Независимое от UI выполнение задач в фоновом режиме
- **Отладочный режим**: Детальное логирование работы планировщика для диагностики

### 💾 Управление артефактами бэкапа

- **Структурированное хранение**: Каждый бэкап создается в отдельной подпапке с именем `<ИмяЗадачи>_yyyyMMdd_HHmmss_<Тип>`
- **Гибкие форматы**:
  - При включенном сжатии: ZIP-архив в подпапке
  - При включенном шифровании: зашифрованный файл `.enc` в подпапке
  - При отключенном сжатии/шифровании: прямое копирование дерева файлов в подпапку
- **Метаданные**: Полная история выполнения с детальной информацией о каждом бэкапе

### 🧹 Политики управления хранением

- **KeepAll**: Сохранять все версии бэкапов без ограничений
- **MaxVersions**: Хранить только N последних версий, автоматически удаляя старые
- **MaxAge**: Удалять бэкапы старше указанного количества дней
- **Автоматическая очистка**: Удаление как записей истории, так и физических файлов/папок

### 📊 Мониторинг и уведомления

- **Журнал операций**: Подробная история всех бэкапов с фильтрацией по статусу и задаче
- **Системные уведомления**: Tray-иконка с уведомлениями о статусе операций
- **Прогресс-бар**: Отображение текущего состояния выполнения с детальной информацией
- **Детальная статистика**: Количество скопированных файлов, общий размер, сжатый размер, длительность выполнения

### 🎨 Пользовательский интерфейс

- **Современный дизайн**: Material Design с использованием библиотеки MaterialDesignThemes
- **MVVM архитектура**: Чистое разделение логики и представления
- **Интуитивное управление**: Вкладки для всех настроек задачи
- **Асинхронные операции**: Отзывчивый интерфейс во время выполнения операций
- **Валидация данных**: Проверка корректности ввода на всех этапах

```bash
dotnet restore

```


## 🎮 Руководство пользователя

### Создание новой задачи резервного копирования

1. **Запустите приложение** и нажмите кнопку **"Создать"** в главном окне

2. **Вкладка "Основные"**:
   - Введите **имя задачи** (обязательное поле)
   - Выберите **папку источника** с помощью кнопки "..."
   - Выберите **папку назначения** с помощью кнопки "..."
   - Установите галочку **"Задача включена"** для автоматического выполнения

3. **Вкладка "Расписание"** (опционально):
   - Выберите тип расписания: **Ручной**, **Ежедневно**, **Еженедельно** или **Ежемесячно**
   - Установите **время запуска** в формате HH:mm (например, 14:30)
   - Для еженедельного расписания: выберите дни недели (можно несколько)
   - Для ежемесячного расписания: выберите число месяца (1-31)

4. **Вкладка "Параметры копирования"**:
   - Выберите **тип бэкапа**: Полный, Инкрементальный или Дифференциальный
   - Установите галочку **"Использовать сжатие ZIP"** (опционально)
   - Выберите **уровень сжатия** (0-9, где 0 - без сжатия, 9 - максимальное)

5. **Вкладка "Шифрование"** (опционально):
   - Установите галочку **"Использовать шифрование AES"**
   - Введите **пароль шифрования** (минимум 8 символов)
   - Подтвердите пароль

6. **Вкладка "Хранение"** (опционально):
   - Выберите **политику хранения**:
     - **Сохранять все**: Все версии сохраняются
     - **Максимум версий**: Укажите количество версий (например, 10)
     - **Максимальный возраст**: Укажите количество дней (например, 30)

7. Нажмите **"Сохранить"** для создания задачи

### Управление задачами

- **Запуск задачи вручную**: Выберите задачу в списке и нажмите кнопку **"Запустить"**
- **Редактирование задачи**: Выберите задачу и нажмите кнопку **"Изменить"**
- **Удаление задачи**: Выберите задачу и нажмите кнопку **"Удалить"** (с подтверждением)
- **Просмотр истории**: Двойной клик по задаче открывает историю выполнения

### Просмотр журнала операций

- Откройте меню **"Вид"** → **"Журнал операций"**
- Используйте **фильтры** для просмотра:
  - По статусу: Успешные, Ошибки, Предупреждения
  - По задаче: Выберите конкретную задачу
- Просматривайте детальную информацию о каждом выполнении

### Расшифровка зашифрованных бэкапов

1. Откройте меню **"Инструменты"** → **"Расшифровать бэкап"**
2. Выберите **зашифрованный файл** (`.enc` или `.zip`)
3. Выберите **папку назначения** для расшифрованных файлов
4. Введите **пароль**, использованный при шифровании
5. Нажмите **"Расшифровать"**

## 🔧 Расширенная настройка

### Политики хранения

#### KeepAll (Сохранять все)
- Все версии бэкапов сохраняются без ограничений
- Используйте для критически важных данных
- Требует больше дискового пространства

#### MaxVersions (Максимум версий)
- Сохраняется только указанное количество последних версий
- Старые версии автоматически удаляются при создании новых
- Рекомендуется для регулярных бэкапов с ограниченным местом

#### MaxAge (Максимальный возраст)
- Удаляются все бэкапы старше указанного количества дней
- Полезно для соблюдения политик хранения данных
- Автоматическая очистка при применении политики

### Типы резервного копирования

#### Полная копия (Full)
- Копируются все файлы из источника
- Используется для создания базовой точки восстановления
- Требует больше времени и места
- Рекомендуется выполнять периодически (например, раз в неделю)

#### Инкрементальная копия (Incremental)
- Копируются только файлы, измененные с последнего бэкапа любого типа
- Быстрое выполнение, экономия места
- Для восстановления требуется полная копия + все инкрементальные
- Рекомендуется для ежедневных бэкапов

#### Дифференциальная копия (Differential)
- Копируются файлы, измененные с последнего полного бэкапа
- Баланс между скоростью и простотой восстановления
- Для восстановления требуется полная копия + последняя дифференциальная
- Рекомендуется для промежуточных бэкапов

### Сжатие ZIP

- **Уровень 0**: Без сжатия (быстро, но занимает много места)
- **Уровень 1-3**: Быстрое сжатие (компромисс между скоростью и размером)
- **Уровень 4-6**: Стандартное сжатие (рекомендуется для большинства случаев)
- **Уровень 7-9**: Максимальное сжатие (медленно, но максимальная экономия места)

## 🔐 Безопасность

### Шифрование

Приложение использует промышленные стандарты криптографии:

- **Алгоритм**: AES-256-CBC (Advanced Encryption Standard, 256-битный ключ)
- **Режим**: CBC (Cipher Block Chaining) с PKCS7 padding
- **Генерация ключа**: PBKDF2 с SHA-256, 10,000 итераций
- **Соль**: Случайная 256-битная соль для каждого файла
- **IV (Initialization Vector)**: Случайный 128-битный IV для каждого файла

### Хранение паролей

Пароли шифрования защищаются с помощью Windows DPAPI:

```csharp
// Пароль шифруется перед сохранением
ProtectedData.Protect(
    passwordBytes, 
    entropy, 
    DataProtectionScope.CurrentUser
)
```

- Пароли хранятся только для текущего пользователя Windows
- Используется дополнительная энтропия для усиления защиты
- Пароли никогда не сохраняются в открытом виде

### Рекомендации по безопасности

1. **Используйте сильные пароли**: Минимум 12 символов, комбинация букв, цифр и символов
2. **Храните пароли безопасно**: Запишите пароли в безопасном месте (менеджер паролей)
3. **Регулярно обновляйте пароли**: Периодически меняйте пароли для критически важных бэкапов
4. **Защищайте папки назначения**: Используйте права доступа Windows для защиты папок с бэкапами
5. **Проверяйте целостность**: Периодически проверяйте возможность расшифровки бэкапов

## 🤝 Вклад в проект

Мы приветствуем вклад в развитие проекта! Вот как вы можете помочь:

### Процесс внесения изменений

1. **Fork репозитория** на GitHub
2. **Создайте ветку** для вашей функции (`git checkout -b feature/AmazingFeature`)
3. **Внесите изменения** и добавьте тесты
4. **Убедитесь, что все тесты проходят** (`dotnet test`)
5. **Закоммитьте изменения** (`git commit -m 'Add some AmazingFeature'`)
6. **Запушьте в ветку** (`git push origin feature/AmazingFeature`)
7. **Создайте Pull Request**

### Рекомендации

- Пишите понятный и документированный код
- Добавляйте тесты для новой функциональности
- Следуйте существующему стилю кода
- Обновляйте документацию при необходимости
- Пишите осмысленные сообщения коммитов
